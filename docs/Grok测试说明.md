# Grok 测试说明

2026-10-17 起，PR 由 Grok bot 测试（JQ 决定）。Claude 和 GPT 负责写代码和互审，Grok 负责照 PR 里的步骤实测并在 PR 里回报结果。

## 1. 流程

1. 作者提 PR，CI 全绿后在 PR 描述“给 Grok 的测试步骤”里写清楚怎么测（格式见第 2 节）。
2. Grok 在测试环境照步骤测，在 PR 里留一条结果：每步通过 / 不通过，不通过附操作、实际结果、日志摘要。
3. 不通过的由 PR 作者修，修完在 PR 里说明，Grok 复测。
4. 测试通过、互审给出“可合并”后，JQ 说“合并”再合。

纯文档、只改 CI 的 PR 写“无需实测”，Grok 只核对文档里的步骤能不能照做。

## 2. 测试步骤怎么写

每个 PR 写下面几项，Grok 不需要读代码就能测：

- **环境**：用哪套环境（测试服务器 / 本地 `deploy/LOCAL.md`），要先部署哪个镜像或分支。
- **前置数据**：要哪些合成部门、岗位、员工、制度页。只用合成数据，名字带 `E2E` 标记，方便测完删除。
- **步骤和预期**：一步一行，写操作和应该看到的结果。
- **必测的拒绝项**（`AGENTS.md` 第 5 节）：无岗位、岗位不符、未授权用户各试一次，应被拒绝。
- **敏感字段**：合成员工填上手机号、身份证号、银行卡号，确认不出现在返回、同步结果和日志里。
- **自动测试**：能用 `tests/e2e` 跑的写命令，例如 `cd tests/e2e && uv run pytest -v -k x4`。

## 3. 给 Grok 的规则

- 不要指向生产环境；测试用的管理员 Key 测完在后台删掉。
- 密钥、Token、员工真实数据不贴进 PR、日志摘要和聊天。贴日志前去掉 Token 和 Cookie。
- 只报结果，不改代码、不推分支、不合并。发现安全问题在 PR 里标“安全”，并告诉 JQ。
- 测完删掉合成数据；删不掉的按 `E2E` 标记列在结果里。
