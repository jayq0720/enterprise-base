# 任务卡 P3-G4：部署员工前台（X6）

- 负责：GPT　审核：Claude　验收：JQ
- 分支：`gpt/P3-G4-portal-deploy`，目标分支 `main`
- 前置：X6 员工前台（`services/portal`）、X4 前台接口、X2 `portal_actions` 已合入 main，`portal` 镜像由 main CI 发布。
- 背景：员工要在电脑浏览器里用 HR 助手、制度问答、请假和审批。上线时会关闭 Dify Web App，员工网页端改由 X6 提供。X6 是独立服务，只通过 HTTP 调 X4、X3 和 Dify 应用 API。服务本身说明见 `services/portal/README.md`。

## 1. 配置

- `.env.example` 和 `make init` 新增（随机生成，重复 init 不覆盖）：`EB_PORTAL_SESSION_SECRET`、`EB_MCP_PORTAL_TOKEN`；两项都 ≥32 位，和 X3/X4 现有三项密钥互不相同。
- 人工填写：`EB_PORTAL_WECOM_CORP_ID`、`EB_PORTAL_WECOM_AGENT_ID`、`EB_PORTAL_WECOM_APP_SECRET`（可以和 `eb_wecom_login` 用同一个企业微信应用），`EB_PORTAL_DIFY_HR_APP_KEY`、`EB_PORTAL_DIFY_POLICY_APP_KEY`（Dify 后台两个应用的 API Key，可留空，留空的应用前台不显示）。
- `EB_PORTAL_IMAGE` 用 main CI 发布的 SHA256 摘要，校验规则和 X3/X4 一样。
- `prepare.py` 生成 `secrets/portal.env`：`EB_PORTAL_PUBLIC_URL=${EB_SCHEME}://portal.${EB_DOMAIN}`，`EB_PORTAL_X4_URL=http://frappe-mcp:8080`、`EB_PORTAL_X4_PORTAL_TOKEN=<EB_MCP_PORTAL_TOKEN>`，`EB_PORTAL_X3_URL=http://kb-gateway:8080`、`EB_PORTAL_X3_TOKEN=<EB_KB_SERVICE_TOKEN>`，`EB_PORTAL_DIFY_API_BASE=http://dify/v1`。`secrets/frappe-mcp.env` 加上 `EB_MCP_PORTAL_TOKEN`。
- 对外 HTTPS 时 `EB_PORTAL_PUBLIC_URL` 必须是 https（X6 启动时会检查）；本机调试用 `http://portal.localhost`。

## 2. 服务和入口

- `frappe-services.yaml` 加 `portal` 服务：`profiles: [portal]`，网络 `default` + `edge`，健康检查 `/healthz`，依赖 `frappe-mcp`、`kb-gateway`。
- `Makefile` 加 `make portal`（先确保 `make hr-assistant` 起来的 X3/X4 带上新 Token 重建）。
- Caddy 加站点 `{$PORTAL_ADDRESS}`（`portal.${EB_DOMAIN}`），**不加** `admin_only`，员工从公网访问；只反向代理到 `portal:8080`，`header_up -X-Forwarded-For` 不用透传（X6 不看来源 IP）。请求体限制 64 KB。
- `make verify` / `validate.py` 补对应检查：portal 站点没有管理员白名单、只有这一个上游；`secrets/portal.env` 权限 600；Token 互不相同。

## 3. 企业微信后台（写进手册，由 JQ 操作）

- 应用“网页授权及 JS-SDK”的可信域名、“企业微信授权登录”的授权回调域，都加上 `portal.<客户域名>`。
- 需要备案域名和公网 HTTPS，和企业微信回调的要求相同。

## 4. 健康检查、备份、发布

- `health_services.py` 把 `portal` 纳入（启用了才检查）。
- `secrets/portal.env` 随密钥目录一起备份；`release.py` 发布顺序在 X3/X4 之后起 portal。

## 验收

- 测试环境 `make portal` 后，`tests/e2e/tests/test_portal.py` 全部通过（e2e 需要把 `EB_PORTAL_WECOM_API_BASE` 指向测试起的假企业微信接口，见 e2e README）。
- 白名单外的地址能打开 `portal.<域名>`，打不开 `dify.`、`hr.`。
- 浏览器开发者工具里看不到任何 Dify Key 或服务 Token；Cookie 只有 `__Host-eb_portal`。
- 手册 `docs/manual/` 补“员工前台”一节：员工怎么登录、企业微信后台怎么配可信域名。
