# 任务卡 P2-G3：岗位上的助手功能开关（配合 Claude P2-C2）

- 负责：GPT　审核：Claude　验收：JQ
- 分支：`gpt/P2-G3-designation-tool-switches`，目标分支 `main`
- 背景：P2-C2 要求“按岗位绑定 X4 工具”。Dify 不能按提问人换工具列表，所以由 X4 在每次调用时按员工岗位判断开没开。开关放在 Frappe 的“岗位”（Designation）上，HR 在后台勾选，不写死在代码里。X4 一侧由 Claude 改（PR 见 `claude/p2-c2-designation-tools`），**本卡要先合入并部署，X4 再升级**：X4 查不到开关字段时按 HR 系统不可用处理，不会默认放开。

## 1. Designation 加 4 个勾选框（自定义字段，导出 fixtures）

| 字段 | 标签 | 管的 X4 工具 |
| --- | --- | --- |
| `eb_tool_leave_query` | 助手可查假期和请假记录 | `leave_balance`、`my_leave_applications` |
| `eb_tool_leave_apply` | 助手可发起请假 | `draft_leave`、确认提交 |
| `eb_tool_approval` | 助手可查待我审批 | `pending_my_approval` |
| `eb_tool_duties` | 助手可查岗位职责 | `my_responsibilities` |

- 类型 Check，默认 1；放在一个“企业微信助手”分节里，排在岗位职责后面。
- 已有岗位升级后也要是勾上的：加一个 after_migrate 补丁，只把空值补成 1，不覆盖 HR 已经取消的勾。
- 只有 HR Manager 能改这些字段（和岗位职责、知识空间同样的权限规则）。

## 2. 放行 X4 查询

- `permissions.py` 的 `X4_COLUMNS["Designation"]` 加上这 4 个字段。X4 的查法：`GET /api/resource/Designation`，`fields=["name","eb_tool_leave_query","eb_tool_leave_apply","eb_tool_approval","eb_tool_duties"]`，`filters=[["name","=","<岗位>"]]`，`limit_page_length=1`。
- 不放行单条记录接口（`/api/resource/Designation/<名称>`），保持现在的白名单方式。

## 验收

- 空库导入 fixtures 后 4 个字段存在、默认勾上；老岗位升级后为 1，取消过的保持 0。
- eb-x4 账号按上面的查法能取到 4 个字段；查其他字段或单条记录接口仍被拒。
- 非 HR Manager 改开关被拒。
- 手册 `docs/manual/` 补一段：在哪里勾、勾掉后员工在企业微信里会看到“你的岗位没有开通……，需要的话请联系 HR”。
