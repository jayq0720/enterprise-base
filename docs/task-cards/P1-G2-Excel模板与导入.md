# 任务卡 P1-G2：组织和岗位职责的 Excel 模板与导入

- 负责：GPT　审核：Claude　验收：JQ
- 分支：`gpt/P1-G2-import`，目标分支 `main`
- 背景：上线前 HR 要把公司的部门、岗位、岗位职责、员工任职一次性导进 Frappe。X3、X4 按员工档案上的部门、岗位和企业微信 userid 判断权限，导错一行就会有人看错或看不到。

## 要做的事

1. **先交模板给 JQ**，做导入代码之前先交。一个 xlsx，四张表：
   - 部门：名称、上级部门
   - 岗位：名称、岗位职责（多行文字）、可见的知识空间（逗号分隔，必须是已有的知识空间）
   - 员工任职：工号、姓名、企业微信 userid、部门、岗位、直属上级工号、入职日期
   - 说明：每列的规则
   
   **不放手机号、身份证号、银行卡、薪资列**。这些由 HR 在后台录，不经过 Excel。
2. **导入**：在 X1 里做，Frappe 后台上传 xlsx。
   - 先全部校验，有错就一行不导，列出“第几张表、第几行、哪一列、什么错”。
   - 全部通过再在一个事务里导入。
   - 校验规则：部门、岗位名不能含英文逗号（`eb_scope` 用逗号分隔）；企业微信 userid 唯一；上级部门、直属上级、岗位、知识空间必须存在或在同一个文件里；同名重复报错。
   - 岗位职责写进 Designation 的 `eb_responsibilities`。多行文字转成段落或列表，X4 会再转回纯文本。
   - 直属上级写进 Employee 的 `reports_to`。请假审批人按 P2-G1 的规则设置。
   - 重复导入同一个文件时更新已有记录，不重复建。
3. 只有 HR Manager 和 System Manager 能导入。

## 验收

- 用一份合成数据的样例文件（放进 fixtures 或测试数据，不用真实员工）导入后，组织、岗位职责和 Excel 一致。
- 故意写错的文件导入失败，错误列表准确，库里没有任何变化。
- 导入后 X4 的 `my_responsibilities` 能查到对应员工的岗位职责（可以跑 `tests/e2e/tests/test_x4.py` 的思路手工验）。
- 测试覆盖：无权限用户导入被拒；文件里出现敏感字段列时拒绝导入。
