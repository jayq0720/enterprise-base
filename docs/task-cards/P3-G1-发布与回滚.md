# 任务卡 P3-G1：生产发布与一键回滚

- 负责：GPT　审核：Claude　验收：JQ
- 分支：`gpt/P3-G1-release-rollback`，目标分支 `main`
- 前置：P3-G2 备份已合入（回滚要靠发布前的备份）。
- 背景：现在升级靠手册里一串命令（先备份、`make init`、`make build`、`bench migrate`、`make hr-assistant`……），容易漏步。方案要求“手动发布、可一键回滚”。本卡把它做成两个命令，在 Claude 的云端测试环境或 CI 里验证，不需要生产服务器。

## 1. `make release`

按固定顺序执行，任何一步失败就停下并提示回滚：

1. 检查：工作区干净、`make verify` 通过、`secrets/.env` 权限 600、要发布的镜像都是 main CI 发布的 SHA256 摘要。
2. 调 `make backup`，记下这次备份文件名。
3. 记录发布前状态：仓库提交号、`secrets/.env` 里所有 `*_IMAGE` 值、Frappe 镜像标签、Dify 版本，写到 `data/releases/<时间>.json`（不含密钥值）。
4. 构建或拉取新镜像 → 起 Frappe → `bench migrate` → 起 Dify → 起 X3/X4/X5 和企业微信入口。顺序要和现有手册一致（例如先 Frappe 再 X4）。
5. 发布后自检：各服务健康检查、Dify 和 Frappe 登录页 HTTP 状态、X3/X4/X5 健康接口。

## 2. `make rollback`

- 默认回到上一条发布记录：恢复当时的镜像值和代码提交，重建容器。
- Frappe 迁移不能倒着执行，所以**有迁移的发布，回滚时要恢复发布前的数据库备份**。脚本根据发布记录判断是否需要，需要时明确提示“将丢失发布后产生的数据”，并要求二次确认。
- 回滚后跑同一套自检。

## 3. 约束

- 不用浮动标签，不用 PR 构建的镜像。
- 不改开源项目源码，不 `down -v`。
- 输出只打印步骤名、成功/失败、HTTP 状态码，不打印展开后的配置和密钥。

## 验收

- 在测试环境从当前 main 发布到一个新提交，再回滚：版本、数据和登录都回到发布前。
- 故意让第 4 步失败（例如给一个不存在的镜像摘要），脚本停下，环境仍可用，`make rollback` 能恢复。
- 手册 `docs/manual/` 补“发布与回滚”一节，写清什么时候必须恢复数据库。
