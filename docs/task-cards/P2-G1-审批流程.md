# 任务卡 P2-G1：请假审批和入职待办（制度发布审核已完成）

- 负责：GPT　审核：Claude　验收：JQ
- 分支：`gpt/P2-G1-workflows`，目标分支 `main`
- 背景：三个流程里，制度发布审核已经在 P2-G 用 Workflow “EB Wiki Review” 做完（HR 专员起草送审，HR 管理员发布），本卡不用再做。剩下两个流程，全部用 Frappe / HRMS 自带功能配置，导出 fixtures，不改源码。

## 1. 请假审批（员工 → 直属上级 → HR）

- 用 HRMS 自带的请假审批人，加上 Leave Application 的 Workflow：
  - 直属上级：Employee 的 `leave_approver`，没有就用部门的请假审批人。
  - 上级批准后转 HR。
- **要兼容 X4**：X4 用 eb-x4 账号新建的请假单是 `status=Open`、`docstatus=0`，审批人用 HRMS 的 `get_leave_approver` 自动填。
  - 加 Workflow 后，X4 新建的单要能自动进入第一个审批状态，不能因为 workflow_state 校验失败。
  - X4 的“待我审批”工具现在按 `leave_approver = 本人` 且 `status=Open` 查。第二级（HR）的待办如果不在这个条件里，在 PR 里写清楚第二级用什么字段区分，Claude 跟着改 X4。
- 只有审批人能批；员工不能批自己的；eb-x4 账号不能提交、审批（P2-G 的限制要继续有效）。

## 2. 入职待办（Employee Onboarding）

- 按岗位配置 Onboarding Template，每个岗位一套待办（例如开通账号、领设备、制度学习），新员工入职时按岗位生成待办，分给对应负责人。
- 模板内容是客户数据，仓库里只放一份合成示例，真实模板由 HR 在后台配。

## 验收

- 合成员工发起请假：直属上级批 → HR 批 → 状态 Approved，余额正确扣减。任何一级退回，状态正确。
- 用 X4（eb-x4 账号）新建的请假单能走完同样的流程。可以用 `tests/e2e` 的请假用例起单，再在后台审批。
- 新建一个岗位的员工，自动生成该岗位的入职待办。
- 测试覆盖：非审批人批被拒、员工批自己的被拒、eb-x4 提交被拒；fixtures 空库导入后复现。
