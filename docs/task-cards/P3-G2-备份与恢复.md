# 任务卡 P3-G2：每日备份与恢复演练

- 负责：GPT　审核：Claude　验收：JQ
- 分支：`gpt/P3-G2-backup`，目标分支 `main`
- 背景：现在三套 Compose（`${EB_PROJECT}`、`-dify`、`-hr`）的数据全在命名卷里，`LOCAL.md` 明确写了“不包含自动备份”。上线前必须能每天备份、能恢复。本卡不需要服务器：脚本在 CI 的临时环境里实测，服务器上只由 JQ 按手册装定时任务。发布回滚（P3-G1）依赖本卡，先做本卡。

## 1. 备份内容

| 组件 | 备份什么 | 建议做法 |
| --- | --- | --- |
| Frappe（MariaDB、附件） | 每个站点的数据库和公开/私有附件 | 原生 `bench --site <站点> backup --with-files`，取出生成的文件 |
| Dify PostgreSQL | 整库 | `pg_dump -Fc`，在 db 容器里执行 |
| Dify 上传文件、插件 | `api` 的 storage 卷、plugin_daemon 卷 | 停写或只读挂载后打 tar |
| Qdrant | 全部集合 | 官方快照接口（`POST /snapshots`），不直接拷正在写的目录 |
| 服务器密钥 | `deploy/secrets/` | 和数据一起加密，解密密钥另存（不放同一台机器） |

- 卷名从 Compose 项目名推出，不写死 `eb`。
- 每份备份带清单文件：时间（北京时间）、各组件版本和镜像摘要、仓库提交号、各文件大小和 SHA256。

## 2. 加密、保留和存放

- 打包后用开源工具加密（例如 `age`，BSD-3），公钥放服务器配置，私钥由 JQ 另存。备份文件权限 600，不进日志。
- 默认保留 7 天每日和 4 周每周，天数做成配置。
- 存放位置做成配置：默认本机目录；异地存储（例如阿里云 OSS）的地址和凭据只放服务器密钥文件，代码里不写服务商地址。

## 3. 入口和定时

- `make backup`：一次完整备份，失败时非零退出、只打印组件名和错误类型。
- `make restore BACKUP=<文件>`：恢复到**新的项目名**（例如 `eb-restore`），不覆盖正在运行的环境；覆盖正式环境要再加显式参数并二次确认。
- 手册里给出 systemd timer（或 cron）的安装步骤，每天凌晨跑一次，由 JQ 在服务器上执行。

## 4. 恢复演练

- CI 里至少实跑 Frappe 这一段：在临时站点造合成数据（员工、岗位、请假单、附件），备份，恢复到第二个站点，核对记录数和附件 SHA256 一致。可以加在现有 frappe-contract 流程里，或新开一个只在 `deploy/` 改动时跑的检查（`.github/` 属于 Claude，需要改时在 PR 里写明，由 Claude 改）。
- Dify 和 Qdrant 的整套恢复由 Claude 在云端测试环境跑一次（和以前 P0、P1-G7 一样），记录耗时。
- 手册 `docs/manual/` 写清：多久备份一次、存在哪、怎么恢复、恢复要多久、恢复后怎么核对。

## 验收

- `make backup` 生成加密包和清单；包里没有明文密钥，日志里没有密钥、员工内容和文件路径以外的数据。
- 恢复到新项目后：Frappe 记录数、附件一致；Dify 应用、知识库文档、Qdrant 检索结果一致；X3/X4/X5 能连上恢复后的环境。
- 过期备份按保留策略删除。
- 恢复耗时写进手册。
