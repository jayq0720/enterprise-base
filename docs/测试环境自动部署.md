# 测试环境自动部署

`.github/workflows/deploy-test.yml`：`main` 上的 `ci` 通过后，GitHub 只把这次提交的 40 位提交号通过 SSH 交给测试服务器，服务器执行 `make -C deploy release REVISION=<提交号>`。发布顺序、备份和自检都由 `make release` 负责，见 `docs/manual/`。

默认关闭。服务器到位、首次手动部署和一次手动 `make release` 都成功后再开。

## 安全边界

- GitHub 只能触发“发布到这个提交”，不能执行别的命令：服务器的 `authorized_keys` 用强制命令，只接受一个 40 位十六进制提交号，其余一律拒绝。
- 密钥和模型 Key 都留在服务器 `deploy/secrets/`，GitHub 上只有这把 SSH 部署钥匙、服务器指纹和登录地址。
- 只认本仓库 `main` 的 push 触发、结论为成功的 `ci`；fork 的同名分支不会触发。
- 同一环境串行，不取消正在进行的发布；数据库回滚要人工二次确认，自动部署不会做回滚。发布失败时按记录手动 `make rollback`。
- 只用于测试环境。生产环境仍然手动发布。

## 开启步骤（服务器到位后）

1. 服务器上用部署账号生成一对专用钥匙（只给 GitHub 用）：`ssh-keygen -t ed25519 -N '' -f ~/eb-deploy-key`。
2. 把强制命令脚本复制到仓库外，避免发布时改到它自己：
   `sudo install -m 755 <部署目录>/.github/scripts/test-release.sh /usr/local/bin/eb-test-release`
3. 在部署账号的 `~/.ssh/authorized_keys` 加一行（`<部署目录>` 换成实际路径）：
   `restrict,command="/usr/local/bin/eb-test-release <部署目录>" ssh-ed25519 AAAA...（eb-deploy-key.pub 的内容）`
4. GitHub 仓库 Settings → Environments 新建 `test`，加三个 Secret：
   - `EB_TEST_SSH_KEY`：`~/eb-deploy-key` 私钥全文。加完后在服务器上删掉这份私钥。
   - `EB_TEST_SSH_KNOWN_HOSTS`：在自己电脑上 `ssh-keyscan -t ed25519 <服务器地址>` 的输出，并核对指纹。
   - `EB_TEST_SSH_TARGET`：`部署账号@服务器地址`。
5. Settings → Variables 加仓库变量 `EB_TEST_DEPLOY=true`。
6. 合一个小改动到 `main`，看 Actions 里 `deploy-test` 成功，服务器 `git rev-parse HEAD` 等于该提交。

关掉：把 `EB_TEST_DEPLOY` 改成别的值，或在 `authorized_keys` 删掉那一行。

## 注意

- 服务镜像（X3/X4/X5）要等 `service-images` 构建完、`deploy/.env.example` 的摘要更新进 `main` 后才会换；只改了服务代码但没更新摘要的提交，发布的是 App 和配置。
- 服务器必须能访问 GitHub 取代码（仓库公开时不需要凭据）和 GHCR 拉镜像。
- 阿里云安全组要允许 GitHub Actions 的出口地址访问 SSH 端口；地址范围见 GitHub 的 `api.github.com/meta`，会变化，按月复核。
