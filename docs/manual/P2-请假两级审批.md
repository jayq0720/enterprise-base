# 请假两级审批（P2-G1，入职待办另交付）

使用原生 Workflow `EB Leave Review`：待主管 → 待 HR → Approved；两级都可退回给员工修改重送，或拒绝。主管通过后仍是 Open/docstatus=0，HR 最终通过才是 Approved/docstatus=1，余额由 HRMS 原生账本扣减；拒绝为 Rejected/docstatus=1，不扣余额。已批准单由原指定 HR 取消，原生冲销余额。

部署前在独立测试环境升级并迁移 App。此配置会启用 Leave Application 工作流；已有其它请假工作流或历史单据的环境应先评估状态映射，不能直接覆盖生产配置。当前无部署服务器，不能据此记为上线验收通过。

HR Manager 在 Employee 上配置 `leave_approver`（没有时用部门第一位请假审批人）和 `eb_hr_approver`（必须是启用且非申请人本人的 HR User 或 HR Manager）。主管（包括部门审批人）需 Leave Approver 角色。审批人写入新单后固定，申请人不能改。HR 缺项时允许先起单，但主管不能转交第二级；补齐员工档案后重新起单。不修改老单审批链。
员工只可为自己起单，HR 可按既有权限代办；X4 继续只能起单，不能提交、审批、修改或删除。X4 原有 Open/docstatus=0 请求自动进入 `EB Leave Manager`，无需新增请求参数。工作流动作及余额处理调用原生 Frappe/HRMS；最小 Hook 只补审批人、校验状态一致和防直接改写，不提升动作执行人的权限。

员工退回后可改日期、类型、事由再重送；审批中的内容冻结。不能直接改 status、docstatus 或替换审批人绕过动作。新单、审批转移及自批均有服务端检查。

给 Claude 的 X4 适配约定：主管待办应按 `leave_approver=本人`、`eb_leave_state=EB Leave Manager`、`status=Open`；HR 待办按 `eb_hr_approver=本人`、`eb_leave_state=EB Leave HR`、`status=Open`。原查询只筛 leave_approver，会漏掉第二级并继续显示已经转 HR 的单据。两个分支都应重新查在职身份；目前本 PR 不改 X4 服务，合入后请按此约定调整。状态/HR 审批人字段均为常规列，不扩大 EB X4 权限。

测试环境验收：用合成员工分别从后台及 X4 起单，主管通过后核对仍 Open、余额未扣；指定 HR 通过后核对 Approved、余额仅扣一次。两级各退回一次再重送；另起单拒绝确认不扣余额。用同角色非指定人、自批、直接改状态/审批人及 eb-x4 提交/删除分别验证拒绝。只回传合成单号、状态、余额差和通过/失败，不贴个人内容或凭据。
