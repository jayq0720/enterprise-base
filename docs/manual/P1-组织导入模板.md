# 组织与岗位导入模板（P1-G2 第一步）

下载 [组织与岗位导入模板.xlsx](../../config/frappe/imports/组织与岗位导入模板.xlsx)，先阅读其中的“说明”页。一个文件对应一家已有公司，公司由后续导入页面选择。

JQ 已确认：HR 先在后台建立员工档案，填写真实的性别、出生日期及工号；Excel **只更新已有员工的任职信息，不新建员工**。后续导入按选定公司及工号查找，找不到或不唯一时整批拒绝，不填写虚构资料。找到后还会核对姓名，和档案不一致也整批拒绝，防止工号写错改到别人。

前三张表各有 3 行纯合成示例，淡黄色标出。正式填写前删除第 2 行起的示例数据，保留工作表名称、列名和文本格式；不要把示例人员混入真实组织。

| 工作表 | 填写内容 |
| --- | --- |
| 部门 | 名称、上级部门；上级可以引用同一文件里的部门 |
| 岗位 | 名称、多行岗位职责、可见的知识空间；多个空间用英文逗号分隔 |
| 员工任职 | 工号、姓名、企业微信 userid、部门、岗位、直属上级工号、入职日期 |
| 说明 | 每列规则、引用方式、必填要求和导入行为约定；不作为业务数据导入 |

**空单元格：** 部门名称、岗位名称、岗位职责、工号、姓名、部门、岗位必填。企业微信 userid、入职日期选填，留空表示不改系统里的原值（userid 也会由企业微信通讯录同步写入，入职日期建档时已填）；上级部门、可见的知识空间、直属上级工号留空表示清空。

工号、直属上级工号和企业微信 userid 使用文本格式，避免前导零丢失；入职日期使用 Excel 日期，显示为 `yyyy-mm-dd`。超过预留的 100 行时，复制上一行格式继续填写，不增加列。岗位职责在单元格内换行，不填 HTML。

引用已有部门时填写完整名称（含公司缩写），引用文件内新部门时填写“部门”表中的名称。岗位、部门名称不能含英文逗号；部门名称、岗位名称、工号、userid 在各自范围内不得重复，员工姓名允许重名。部门上级和员工上级不能形成循环。

“可见的知识空间”填写已有 **EB Knowledge Space 记录的完整名称**，不能用 Wiki Space 名称或 Dify 知识库 ID 代替。留空表示岗位不指定额外知识空间，全员、部门可见仍由知识空间设置决定。合成示例全部留空，避免假设目标系统已经建好空间。

不要增加手机号、身份证号、银行卡或薪资列，也不要把它们写进其他单元格。这些信息由 HR 在 Frappe 后台录入。不要使用公式、合并单元格或新增工作表。

当前仅交付模板及 [表结构约定](../../config/frappe/imports/template.schema.json)，尚未交付后台导入功能，不能把此文件直接交给 Frappe 原生 Data Import。当导入功能完成后，将限制 HR Manager/System Manager 使用，先校验全文件，有错一行不导；通过后在一个事务内写入，重复导入更新已有记录。请假审批人按 P2-G1 单独配置，不增加 Excel 列。
