# 企业微信回调协议准备（P2-G2，尚未接通审批卡片）

`enterprise_base.wecom.crypto` 仅提供签名、AES-CBC 解密、企业 ID 校验和受限 XML 解析；本次没有注册公网接口、推送卡片或执行审批。后续卡片回调必须在验签后按真实 userid 查在职员工，用该员工自己的 Frappe 用户执行 Workflow，并单独做重复点击和后台状态更新验证。

实现依据企业微信官方[加解密方案](https://developer.work.weixin.qq.com/document/path/90968)：SHA1 排序签名、32 字节 AES Key、Key 前 16 字节作 IV、32 字节 PKCS#7 填充、网络字节序长度及尾部 CorpID。签名常量时间比较，限制时间偏差 300 秒；错误统一固定文案，不暴露配置、密文、明文或原始异常。XML 拒绝 DTD、实体、重复字段、NUL 和超限输入。

使用 Frappe v15.123.1 已依赖的 cryptography（该版本要求 `~=50.0.0`，Apache-2.0/BSD-3-Clause），不增加生产依赖、不内置真实 Token/AESKey。测试密钥是公开的字节序列 0–31，仅用于合成向量；向量由独立 OpenSSL AES 实现生成，验证合法解密、错误填充、长度、企业 ID、签名、时效和 XML 拒绝。

本地四项离线测试通过，不代表收到过真实企业微信回调。后续发送/更新须依[消息发送](https://developer.work.weixin.qq.com/document/path/90236)、[事件格式](https://developer.work.weixin.qq.com/document/path/90240)和[模板卡片更新](https://developer.work.weixin.qq.com/document/path/94888)接入；更新凭证仅 72 小时有效且只能使用一次，后台审批也要保存并消费发送接口返回的凭证。普通聊天和审批事件共用应用时，必须统一分发，不能直接替换回调地址而丢掉 dify-on-wechat 消息。
