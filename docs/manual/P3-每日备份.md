# 每日加密备份（P3-G2）

## 配置并首次执行

1. JQ 在另一台可信机器用官方 age 生成解密私钥，妥善离线保存；服务器只接收对应的 age 公钥，不上传私钥到服务器或仓库。
2. 在服务器 `deploy/secrets/.env` 填 `EB_BACKUP_RECIPIENT=<公钥>`，补 `EB_BACKUP_DIR=data/backups`、`EB_BACKUP_DAILY=7`、`EB_BACKUP_WEEKLY=4`。已有环境手动补配置，不为备份重跑初始化或升级镜像。
3. 确认 `deploy/secrets/` 及其子目录权限 700，全部文件权限 600，属主为运行备份的用户；拒绝链接、硬链接和 age 私钥。非默认目录用绝对路径，提前创建为同一用户所有的 700 目录。
4. 首次运行前按下节放置 age，然后执行 `make -C deploy verify`。核对磁盘能容纳一份完整明文暂存和一份加密包，另留足现有服务空间。
5. 在维护窗口执行 `make -C deploy backup`；与首次部署相同，运行用户须能调用 Docker、uv 和 Git。成功只输出“备份:成功”；失败非零退出，只输出组件/错误类型，不展示原始输出或配置。需要自定义 uv 路径时用 `UV=/绝对路径/uv`。
6. 在配置目录查找本项目最新 `.tar.age`，确认权限 600；清单 `manifest.json` 在加密包内，不另写明文清单。备份包括各站数据库与附件、所有非模板 PostgreSQL 库、插件与上传文件、Qdrant 快照、Caddy 证书、已创建的企业微信会话卷以及整个服务器 secrets。
7. 新备份成功且明文清理完成后，才删除本项目过期包；默认最近 7 天及最近 4 周的每周最新一份，其它项目不删除。异地目录可配置到已挂载的私有存储；挂载地址与凭据只放服务器密钥配置，由 JQ 安装，脚本不内置服务商或自动传输命令。

备份时整套应用暂停写入，结束后只恢复原先运行的服务并等健康检查通过。备份、后续恢复和发布须使用同一部署目录的 `data/operations.lock`；同一部署只运行一份 checkout，维护期间不要并发启动服务、建站或改配置。首次默认目录在 Git 忽略的 `deploy/data/backups/`；仓库其它位置不可存包。明文只进入同分区的私有 `.backup-clear-*` 暂存区，成功或异常退出均清理。SIGTERM/SIGINT 会延迟到收集及服务恢复完成后退出；不要强杀进程。断电或 SIGKILL 无法执行清理，恢复后先确认没有备份进程、服务已恢复，再由运维清理残留私有暂存目录。

## age 离线放置

1. 在能联网的机器读取 `deploy/age.lock.json` 的 `linux-amd64` 条目，下载其官方发布包。
2. 核对下载包 SHA256，解出 `age`、`age-keygen`、`LICENSE`，逐个核对锁文件中的文件摘要。
3. 将这三个文件放入服务器 `deploy/data/tools/age-1.2.1/linux-amd64/`，目录 700，两个程序 700，LICENSE 600，属主为备份用户。
4. 执行 `make -C deploy verify`；摘要一致直接使用离线文件，不再下载。工具及许可证说明见 [备份包格式](P3-备份包格式.md)。不要改锁文件来绕过校验。

## 每日北京时间 03:00 定时（服务器到位后由 JQ 安装）

先手动完成一次成功备份。将 `/srv/enterprise-base` 和 `enterprise-ops` 替换成实际部署路径和 Docker 授权用户；该用户的 PATH 中须有 Docker、uv、Git。用 `uv python find 3.12` 查出解释器绝对路径，替换下面的 `/path/to/python3.12`。定时器直接执行同一个 Python 入口，确保终止信号送达备份进程；服务器不必修改系统时区。

`/etc/systemd/system/enterprise-backup.service`：

```ini
[Unit]
Description=Enterprise encrypted backup
After=docker.service
Requires=docker.service
[Service]
Type=oneshot
User=enterprise-ops
WorkingDirectory=/srv/enterprise-base/deploy
Environment=PATH=/home/enterprise-ops/.local/bin:/usr/local/bin:/usr/bin:/bin
ExecStart=/path/to/python3.12 backup.py secrets/.env
UMask=0077
KillMode=process
TimeoutStartSec=infinity
TimeoutStopSec=infinity
```

`/etc/systemd/system/enterprise-backup.timer`：

```ini
[Unit]
Description=Daily enterprise backup
[Timer]
OnCalendar=*-*-* 03:00:00 Asia/Shanghai
Persistent=true
Unit=enterprise-backup.service
[Install]
WantedBy=timers.target
```

JQ 审核路径、用户和维护窗口后执行 `sudo systemctl daemon-reload`，再执行 `sudo systemctl enable --now enterprise-backup.timer`，用 `systemctl list-timers enterprise-backup.timer` 核对下一次运行时间。`Persistent=true` 会在错过定时时补跑；补跑也会暂停应用。取消正在执行的任务用 `sudo systemctl stop enterprise-backup.service`，等待原生收集和服务恢复，不设置强制终止超时。只需每日计时，不在本次开发中安装或启用。

本地与 CI 使用真实 age、真实进程锁和 Docker 命令替身验证入口，未运行整套 Docker 恢复；真实 Frappe 恢复基线见 [恢复演练](P3-Frappe恢复演练.md)。`make restore`、正式覆盖的显式参数/二次确认及全组件恢复将在后续 PR 接入；目前不要把“加密包生成成功”当作整套恢复验收通过，Dify/Qdrant 恢复耗时由 Claude 云端演练后补录。
