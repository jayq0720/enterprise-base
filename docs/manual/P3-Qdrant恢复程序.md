# Qdrant 原生恢复程序（P3-G2）

`deploy/restore_qdrant.py` 是完整恢复入口的内部模块，须在 `restore_guard.prepared` 完成整包校验、新项目隔离并持锁后调用。只支持备份收集程序已确认的单节点全存储快照，不用于分布式集群；统一 `make restore` 仍待接入。

程序复核目标应用已停写、Qdrant 容器停止、镜像 ID 一致、数据命名卷属于新项目且完全为空，不接受源项目、旧卷、绑定宿主目录或自定义非 root 运行用户。使用同一锁定版本官方镜像及原生 `--storage-snapshot`，不传 `--force-snapshot`。原容器保持停止，恢复由独立临时容器完成；它无网络、不加载业务密钥、关闭遥测与容器日志。

快照仅复制进本次临时容器，在原生恢复完成并出现启动标记后正常停止，检查退出码为 0，再删除临时容器及其快照副本。失败或超过 10 分钟仍未就绪时停止后续操作并尝试清理；目标卷可能已有部分内容，必须保持关闭，人工确认后清理并重建新项目。程序不覆盖旧环境，也不自动接流量；清理失败需要运维排查残留临时容器。

本机协议测试覆盖隔离、权限拒绝、命令参数、失败/超时清理及脱敏。新增原生 CI 用固定官方 Qdrant 构造两个合成集合和一个别名，获取完整快照，实际恢复到新卷，再核对集合、别名检索、点 ID 与合成 payload；结果和耗时在 PR 中记录，CI 完成前不宣称实测通过。这是 Qdrant 独立恢复验证，全套 Dify 知识库与 X3/X4/X5 联测仍由 Claude 云端完成，服务器截图待补。无新增依赖，不改上游源码或 `.github/`。
