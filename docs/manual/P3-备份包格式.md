# 备份包格式与校验（P3-G2）

本模块供备份和恢复入口调用；`make backup` 操作及定时安装步骤见 [每日备份](P3-每日备份.md)，隔离恢复见[完整恢复](P3-完整恢复.md)，异地自动传输尚未接入。`pack` 接受已停止写入、准备好的普通文件目录；拒绝链接、保留文件名和多余清单字段，使用官方 age 1.2.1 公钥加密。公钥由服务器配置提供，私钥由 JQ 另存；此模块不生成或保存生产私钥。工具按 `age.lock.json` 核验发布包和程序摘要后缓存到被忽略的 `deploy/data/tools/`，保留 LICENSE；首次校验需联网。

包内 `manifest.json` 记录北京时间（带时区）、仓库提交、项目、版本/镜像以及各文件大小和 SHA256；整个 tar 流直接送入 age，不落盘明文 tar，最终加密文件权限 600，原子发布且不覆盖旧包。调用方须在加密完成后清理已收集的明文源目录；本模块不删除调用方的源数据。`unpack` 仅解包到不存在的新目录：私钥解密后先逐项检查路径、普通文件类型、重复项、清单/大小/摘要，再写文件；目录 700、文件 600。解密临时 tar 随调用清除，解包出的目录供恢复使用，恢复命令须负责最后清理。

`prune` 仅管理同一项目的标准 `.tar.age` 文件名，默认保留最近 7×24 小时的文件，并在最近四周内按北京时间 ISO 周保留至多四个周槽的最新包；配置允许 1–365 天、1–104 周。其它项目、非标准文件和链接不删除。由完整备份成功后调用，不因新备份失败删除旧包。`make -C deploy verify` 用真实 age 执行往返加密、权限、不覆盖、错误私钥/篡改、恶意 tar、保留策略和损坏工具包拒绝检查；全部只使用临时合成文件。

**离线放置 age。** 国内服务器经常连不上 GitHub 发布文件。这时在能联网的机器上下载 `age.lock.json` 里对应平台的官方包，解压后把 `age`、`age-keygen`、`LICENSE` 三个文件放到服务器的 `deploy/data/tools/age-1.2.1/linux-amd64/`。三个文件的摘要和锁文件一致时直接使用，不再联网；不一致会重新下载，下载失败时报错并提示这个目录。上线前跑一次 `make -C deploy verify`，确认工具已经就位，不要等到第一次每日备份才发现。

**解密临时文件。** `unpack` 先把解密后的明文 tar 写到临时文件，默认放在目标目录所在的目录，和恢复数据在同一分区，不使用可能空间很小的 `/tmp`。调用方也可以用 `work_dir` 指定已存在的目录；临时文件权限 600，用完即删。
