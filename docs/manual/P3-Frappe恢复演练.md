# Frappe 备份与恢复演练（P3-G2）

本篇记录任务的原生 Frappe CI 演练；`make backup`、保留策略及定时安装见[每日备份](P3-每日备份.md)，`make restore` 见[完整恢复](P3-完整恢复.md)。不要把 CI 的临时目录或测试脚本用于生产恢复。

`frappe-contract` 先完成两个空站点的权限测试和配置导入，再创建合成员工、岗位、请假单和两份公开/私有附件。使用固定 Frappe v15.123.1 的原生 `bench backup --with-files --ignore-backup-conf`，数据库、公开文件、私有文件及站点配置分别保存到仅当前用户可访问的临时目录。

脚本新建 `recovery.local` 空站点后，才以 `bench restore` 恢复数据库和两份附件；站点若已存在，建站失败并停止。恢复来源站点的加密密钥以验证 API Secret 可解密，保留目标数据库的独立名称/密码，暂停调度器，再迁移和核对。不会覆盖原来的两个站点，不发送真实企业微信消息。

核对四类记录总数、三条合成记录、附件 SHA256/公开私有标记、岗位已关闭值，以及合成 API 凭据能解密；另在恢复站点执行 HTTP 权限契约检查。日志只输出固定结果和总耗时，不输出备份内容、密钥或员工信息；临时备份和核对文件用完即删，不作为 Actions 产物上传。

2026-10-19 [首轮成功 CI 39200994597](https://github.com/qianjie0720-sys/enterprise-base/actions/runs/39200994597) 的全流程耗时为 **50 秒**（含合成数据准备、备份、新建空站、恢复、迁移及核对），原有两空站点各49项测试通过。这个基线只涉及小量合成数据、已缓存镜像和临时 CI 磁盘；生产耗时必须按实际数据库/附件规模重新演练，每轮日志会记录本轮总耗时。这里测的是同一锁定组件版本下的单站点原生恢复，不代表独立 Compose 项目、Dify/Qdrant 或生产数据库已完成恢复验收；后续完整恢复需在隔离项目验证后再由 JQ 安排服务器演练。
