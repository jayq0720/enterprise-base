# 发布与回滚开发验收说明（P3-G1）

日常发布、失败处置、二次确认和容量/保留策略统一见[部署运维手册](部署运维手册.md#发布与回滚)，本篇仅保留开发机制与证据。

- 控制器验证目标属于main、代码/运行镜像基线一致，独立verify后备份并保存原状态；迁移前先停写，先Frappe后X4，自检通过才记录ready。
- 构建准备失败时旧服务仍运行，但代码/镜像配置可能已经更新；按当次记录回滚后重试，不手改状态或指纹。
- 正常发布总会迁移全站，回滚须恢复发布前数据；未进入迁移的失败记录可仅回退代码/镜像。
- 数据覆盖要求显式参数、离线私钥及交互终端二次确认；保留目标数据库凭据，只导入解密密钥，不自动回滚。
- 数据恢复失败保持应用停止、记录rollback-failed，保留原包与记录；重试重新预检、二次确认，不继续半恢复环境。
- 本机/CI覆盖真实Git、锁、加密包、故意构建/迁移失败、内部备份复用锁与同记录重试；Docker调用使用替身，原生数据库组件另有CI演练。
- 云端完整候选演练见[PR #112](https://github.com/jayq0720/enterprise-base/pull/112)：发布492秒、数据回滚262秒，均e2e 11通过/1跳过；使用测试仓库、本地提交和构建垫片，不作为私有GHCR或完整冷构建验收。
