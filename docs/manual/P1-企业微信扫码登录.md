# P1-G3 企业微信扫码登录

仅登录 HR 已建档并绑定的账号：Employee.wecom_userid 唯一、状态 Active、关联 User 已启用且有 Employee 角色。未知、离职、停用、未绑定账号均拒绝，不自动创建用户。请由 HR Manager 在后台维护绑定。

在服务器 `sites/<站点>/site_config.json` 增加 `eb_wecom_login` 对象，配置 `enabled: true`、`corpid`、`agentid`、`app_secret`、`callback_url`。值由管理员填写；不要提交此文件、截图密钥或把密钥写进命令历史。文件应只允许 Frappe 服务账号读取。未配置时扫码登录关闭；关闭开关后未完成的扫码也拒绝。

`callback_url` 必须是 `https://<HR域名>/api/method/enterprise_base.wecom.login.callback`，不带查询参数。企业微信自建应用配置可信域名、网页授权和应用可见范围；按企业微信后台要求完成域名验证。应用 Secret 只授予所需范围。

浏览器打开 `https://<HR域名>/api/method/enterprise_base.wecom.login.start` 即进入扫码页，可作为员工书签。成功进入 `/app`，失败回到 `/login?wecom=failed`，由 HR 核对绑定和状态；不要收集回调 URL（包含一次性 code）。只支持 HTTPS。五分钟浏览器绑定 state 单次消费，禁止复用或跨浏览器打开回调。

继续遵守部署手册的 HR 来源 IP 白名单，入口、回调和 Desk 都需要网络可达。本 PR 不扩大公网开放路径。员工公网访问需要单独评审完整入口策略，不能仅放开回调。反向代理不得记录查询参数、Cookie 或请求头；当前入口不启用访问日志。

本扩展使用企业微信身份认证，调用 Frappe 原生会话创建、登录 IP 和时间限制；Frappe 密码登录的二次验证不会在此重复执行，应在企业微信侧配置所需身份验证策略。

验收：

1. CI 使用真实 Frappe/HRMS 空库和合成账号，模拟企业微信响应；覆盖成功、未绑定、Left、停用、角色不符、跨浏览器、重放和超时/错误响应。
2. 测试环境准备好后，由在职员工实际扫码，确认进入自己的账号；再用未绑定与离职账号确认拒绝，并核对原生 IP/时间限制。此项仍待真实企业微信联测，CI 不能代替。
3. 只记录成功/失败和测试编号，不复制人员资料、Cookie、code、Token 或 Secret。

官方依据：[Web 登录](https://developer.work.weixin.qq.com/document/path/98174)、[获取登录身份](https://developer.work.weixin.qq.com/document/path/98176)。采用 userid 最小扩展，避免通用社交登录按邮箱匹配或自动建户。
