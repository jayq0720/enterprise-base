# 按岗位生成入职待办（P2-G1）

采用原生 Employee Onboarding Template、Employee Onboarding、Project、Task 和 ToDo。App Hook 只在 HR Manager/System Manager 保存 Active 员工时组装并提交原生入职单，不提升当前用户权限。缺项时保留员工档案并提示 HR 补齐，补齐后再次保存即可重试。

按 JQ 2026-10-17 确认保留原生招聘前置：Employee 必须关联真实 Job Applicant，同一应聘者只对应这一份员工档案；必须有唯一、同公司、同岗位、已提交的 Job Offer。不创建占位应聘者/录用通知，不跳过必填字段。已有未取消入职单时不重复创建，重复保存不会新增任务。

HR Manager 打开 Employee Onboarding Template，复制 `EB Synthetic Onboarding` 合成示例，改名后填写公司、岗位及可选部门。每个公司/岗位/匹配部门只保留一套模板；不要直接给仓库示例绑定客户公司。示例无公司/岗位，不会自动匹配员工。真实模板由 HR 在后台维护，复制到客户自己的配置归档，不能把人员和客户模板提交共享仓库。

每项活动填写明确的启用 User 负责人，并清空 Role，避免给整个角色群发个人待办；可以使用原生 begin_on、duration、description 和权重。关闭 `required_for_employee_creation`：本流程是员工建档后补入职待办，不能产生“完成任务才能建员工”的环。此配置不发送欢迎邮件或任务邮件；原生 ToDo 显示在负责人的后台。

HR Manager 仅增加“自己创建的 Task”的读取/分享权限，以满足原生任务分配检查；不增加全体 Task 的读取范围。负责人通过原生任务分享获得对应任务的访问权。该权限随 Task customization 导出，保留其它既有角色规则。

在员工档案填写真实入职日期、假日表、公司和岗位，并关联招聘记录，再由 HR Manager 保存。原生入职单提交后可查看关联的 Project、三个示例 Task 和负责人的 ToDo。HR User 可以按原有权限维护档案，但不能借保存档案自动提交入职单或修改模板，需要 HR Manager 再保存触发。

验收：独立测试站点用合成应聘者、已提交录用通知及新岗位复制模板，指定三个活动负责人。新建对应员工应自动生成一张已提交入职单、三个任务和三个 ToDo；重复保存数量不变。去掉招聘记录、取消录用通知、移除负责人或复制出冲突模板时不生成待办，补齐后可重试；HR User 修改模板/自动提交被拒。

原生配置导出入口为 `enterprise_base.integration.export_configuration`，导出 App 合成模板 fixture 和模板权限 customization；CI 导出后回填 `config/frappe/p2-onboarding/`，再由第二空库导入复测。客户真实模板另按原生过滤条件导出，仅留客户服务器配置归档，包含人员信息的文件按运维备份保护。真实客户后台验收仍待部署环境。
