# 发布版本和回滚依据

`deploy/release_state.py` 是发布入口的状态模块，供后续 `make release/rollback` 在同一维护锁内调用，当前不能单独完成发布或回滚。

发布入口先刷新 main 引用。前置模块拒绝脏工作区、非完整提交号、未合入 main 的提交、权限不是600的服务器配置、浮动镜像及错配服务。当前运行配置的三项服务镜像必须和当前提交的 `.env.example` 一致；目标镜像只采用目标 main 中已经审核锁定的摘要白名单，不接受宿主机环境变量替换，也不从 PR 镜像或浮动标签选取。镜像发布来源仍由版本表审核保证，不把格式检查说成镜像签名验证。

发布前状态写入 `deploy/data/releases/<UTC时间及随机编号>/release.json`，目录700、文件600，包含项目名、前后仓库提交、三项服务摘要、Frappe镜像标签、Dify上游提交、实际运行镜像ID以及备份摘要；不保存完整环境变量、Docker inspect、员工或凭据。`before.tar.age` 是完整加密备份的独立副本，每日备份清理不会删除它。发布记录和专用备份只有在确认不再需要回滚后才由运维清理，不自动套用每日保留策略。

状态原子写入并同步到磁盘；迁移前先写 `migration-started` 和 `restore_database=true`，再执行迁移。失败、重试或回滚失败不清除此标记。即使迁移没有正常返回，也必须恢复发布前数据库，不能靠切回旧镜像恢复。读取记录先核验加密备份SHA256，损坏或缺失时拒绝后续回滚。

此模块的测试使用真实临时Git仓库，验证main与PR边界、脏工作区、镜像摘要及服务对应关系、600权限、敏感数据不入记录、备份独立留存、损坏拒绝和写入故障保持旧记录；不启动业务容器。完整发布、数据库回滚和失败步骤恢复由入口与后续测试接入，截图待服务器截图。没有新增依赖。
