# 岗位上的助手功能开关（P2-G3）

先部署含本卡的 Frappe App，备份后构建、迁移并重启；再升级 Claude 的 X4 岗位开关版本（P2-C2）。两项都部署后，员工每次调用助手工具时才会读取岗位开关；仅部署 Frappe 字段不代表 X4 已启用校验。沿用部署手册和测试环境升级流程，不在线上直接改表。

HR Manager 在后台打开“岗位（Designation）”，在“岗位职责”后的“企业微信助手”分节维护四项：

| 勾选项 | 对应助手功能 |
| --- | --- |
| 助手可查假期和请假记录 | 假期余额、自己的请假记录 |
| 助手可发起请假 | 起草请假及确认提交 |
| 助手可查待我审批 | 查询当前分给自己的审批单 |
| 助手可查岗位职责 | 查询自己岗位职责 |

四项默认开启；已有岗位升级时空值补为 1，HR 明确取消的 0 保持关闭，重复迁移不会重新勾上。只有 HR Manager（及内置 Administrator）可以改开关；其他角色在后台只读，REST 修改同样会被服务端拒绝。普通 HR User 仍可按原有权限新建默认开启的岗位，不得指定关闭或修改已有开关。

取消后，X4 会提示“你的岗位没有开通……，需要的话请联系 HR”。关闭“发起请假”后，已经起草但尚未确认的申请也须重新检查，不能继续确认提交。重新勾选后可恢复使用。具体提示和每次调用校验由 Claude 的 P2-C2 提供；功能开关不替代原有员工身份、数据范围或工作流审批权限。

技术账号只可用 Designation 列表按非空岗位名精确查 name 与四个开关（保留原岗位职责只读字段）；整条记录、其他字段和模糊/无过滤查询仍拒绝。配置用原生 export_configuration 导出为 App fixtures/customization 和 config/frappe/p2-tool-switches 快照；客户的勾选结果是业务数据，留在客户数据库，不作为共享 fixtures 导出。

验收先在独立环境核对默认值、升级及关闭保留，再用 HR Manager 开关、HR User 越权和 eb-x4 精确读取检查；客户后台和企业微信实际提示仍待部署后与 P2-C2 联测，CI 的原生 REST 结果不能代替线上验收。

上线前由 HR 检查所有需要使用助手的在职员工是否已关联真实岗位，补齐未分配或已失效的岗位。没有岗位或岗位不存在时，X4 拒绝这四类功能；字段缺失、空值或查询被 Frappe 拒绝时返回“HR 系统暂时不可用”，不会按默认开启处理。不要为通过检查而给员工批量填一个虚构岗位。

升级时先备份并在测试环境重建 Frappe App 镜像，对实际站点执行原生 `bench --site <站点名> migrate`，重启相关 Frappe 服务并核对字段/权限；已有镜像时只执行 `make up` 不会完成 App 重建与迁移。确认 Frappe 验收通过后，在 `deploy/` 执行 `make init`、`make hr-assistant`，按 [HR 助手部署手册](P1-HR助手部署与验收.md) 更新 X4。`make init` 会把旧环境的 X4 镜像摘要更新到当前 `.env.example`，保留已有密钥；运行中的容器要等后续重建才会换版本。

当前锁定的 X4 来自 [main bb82cca 发布](https://github.com/qianjie0720-sys/enterprise-base/actions/runs/39188132593)，包含 P2-C2 及缺岗位/缺值拒绝修复；具体摘要和许可证见 [版本表](../../deploy/VERSIONS.md)。旧版镜像没有岗位开关校验，不能只根据健康检查成功判定升级完成。

部署后用合成员工和岗位逐项验收，表中结果目前均待客户测试环境执行：

| 操作 | 预期结果 |
| --- | --- |
| 新岗位默认值、旧岗位升级、重复迁移 | 四项默认 1；旧空值补 1；明确关闭的 0 不变 |
| HR User 或普通员工通过页面/REST 改开关 | 页面只读；REST 拒绝；原值不变 |
| eb-x4 精确读取四开关；再请求其他字段/单条记录 | 精确列表返回 1/0；越界读取拒绝 |
| HR Manager 逐项关闭，再问对应助手功能 | 提示岗位未开通；其他已开启功能仍可用 |
| 起草请假后关闭发起请假，再确认 | 确认被拒，Frappe 没有新建请假单 |
| 起草后移除岗位，再确认 | 确认被拒，没有新建请假单 |
| 无岗位、岗位失效或开关配置不可读 | 拒绝或报系统不可用，不回落为开启 |
| 恢复原岗位及开关、重新发起请求 | 重新查询配置后恢复；恢复配置本身不补建单，每次确认仍重新校验 |

仅回传镜像摘要、各项通过/失败和去标识的错误类型，不贴 API 凭据、会话令牌、真实 userid 或员工内容。升级异常时先暂停助手入口，保留 HR 的关闭值；在测试环境排查并按备份恢复，不回退到绕过岗位检查的旧 X4。
