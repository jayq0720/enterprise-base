# 组织任职导入接口（P1-G2）

先使用模板 PR #33；HR 先建员工档案。仅 HR Manager/System Manager 可调用 POST `enterprise_base.duties.org_import.import_workbook`，参数为私有上传文件的 `file_url`、已有 `company`、`save`（0 预检、1 保存）。文件最多 2 MB，每表最多 1000 行。返回错误的工作表/行号/列名/原因或各表数量，不回传员工内容；保存时重新校验，失败整批回滚，不新建员工。

工号在所选公司内必须唯一且已有，姓名用于核对身份，不修改姓名、用户、员工状态或敏感字段。已有企业微信 userid 的转移须先由 HR 处理，不能通过互换两行绕过占用检查。System Manager 若不兼任 HR Manager，不能改变身份关联或知识空间可见范围；这些限制与既有 P2 权限一致。HR Manager 仍须具备原生创建/写入权限，维护新岗位时保留 HR User 角色；HR User 单独不能导入。接口不会提升其手工限制的范围。

部门按层级写入，岗位职责转为转义后的 HTML 段落，直属上级仅写 reports_to。请假审批人按 P2-G1 配置。原生文档校验失败仅返回当前表和行及回滚说明，不打印原始异常或单元格内容。后台上传页面由后续同任务 PR 提供；尚未声称通过企业微信/X4 实际联测。
