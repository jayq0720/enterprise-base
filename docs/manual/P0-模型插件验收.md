## 逐项执行

1. 插件 → 市场，分别安装以上三个官方插件。在设置 → 模型供应商中录入凭据。千问选择国内服务地域；豆包使用该账号已开通的接入点；DeepSeek 使用官方国内 API。记录实际模型标识/接入点类型和服务地域，不记录 Key 或完整客户接入点 ID。每个供应商单独测试一次成功响应，失败时只记录脱敏错误码。
2. 工作室 → 新建测试 Chatflow：开始 → LLM → 回复。系统提示写“你是测试助手，只回答测试问题”，测试问题统一为“请回复：P0 测试成功”。先选千问，保存并运行；改成 DeepSeek，再运行；再改回同一个千问模型，再运行。核对应用 ID 未变、只改模型配置，没有代码改动或容器重启；三次分别留证。按同样方式补一次豆包响应。
3. 仅对这个测试应用依赖的 DeepSeek 插件做卸载/重装实验。先通过界面导出脱敏 DSL 并记录插件固定版本；不提交含凭据或客户 URL 的导出。若界面禁止卸载正在使用的插件，记录拦截行为，再在测试应用副本移除依赖后验证重装。若允许卸载，记录模型节点是否保留、何时报依赖缺失；重装同版本后再次运行，记录是否需要重新选择模型或补填凭据。绝不以“插件重新出现在列表”代替应用恢复测试。
4. 准备两个纯测试文档：`P0-差旅规则` 内容为“测试出差申请需提前三天提交”，`P0-设备规则` 内容为“测试设备报修需提供资产编号”。新建测试知识库，选千问的可用 Embedding 固定模型标识；两篇文档索引完成后，在检索测试问“测试出差需提前几天申请”，记录是否命中差旅文档。启用千问可用 Rerank 模型后重复查询，记录具体模型、命中结果和错误码。不要把 Embedding 成功当成 Rerank 成功。
5. 检查已安装插件列表及各供应商配置，只保留本次批准的国产模型插件。检查实际请求目标的域名与地域，避免将千问国际地域接入点当作国内处理；请求核对只看目标域名与状态，不复制请求体、请求头或令牌。
6. 核对部署环境中的 Next.js 遥测关闭、更新检查地址为空、Sentry DSN 为空、Amplitude Key 为空、插件 Sentry 关闭。G1 已写入相关配置，但“有配置”与“没有外联”分开记录。通过现有防火墙/代理的目标域名统计或浏览器网络面板确认是否仍有非必要外联；Marketplace、插件依赖下载及模型服务分别归因。截图中移除 Cookie、Authorization、Key 和查询内容，不生成带完整请求的 HAR 上传。

模型插件的遥测也需单独核对：供应商插件可能带统计请求头或自身遥测，Dify 主程序的开关不代表它们全部关闭。若目标是严格禁止境外外联，需要在测试出口做域名白名单并重测安装、Embedding、Rerank 和推理；没有出口证据时，2.5 只能写“部分/待测”。
