# P3-G2：备份数据收集模块

`deploy/backup_collect.py` 是供备份入口调用的收集模块，尚未提供 `make backup`，不要单独用它代替完整备份。后续入口负责独占锁、终止信号处理、复制服务器密钥、加密和清理暂存文件；恢复命令、异地存储及每日定时任务也尚未接入。

模块按三个 Compose 项目的精确标签寻找实际容器和默认网络，使用正在部署的镜像 ID 和原容器卷，不依赖镜像标签重新拉取或重建配置。只接受私有的空暂存目录；拒绝正在运行的维护任务、重复实例、暂停或重启中的容器。先停止全部原先运行的应用容器，保留数据库、Redis、Qdrant；成功、异常都会尝试恢复全部已停止服务，原先关闭的服务保持关闭；恢复后等这些容器都在运行且健康检查通过（最长约 5 分钟），否则报 `恢复服务:Exited` 或 `恢复服务:Unhealthy`，此时备份视为失败，需人工检查服务。收集期间整套应用不可用（企业微信回调会失败，企业微信会自动重试，但窗口过长时消息可能丢失），调用方应安排维护窗口且禁止并发发布、建站和直接写数据库。

每个 Frappe 站点执行原生完整备份（数据库、公开/私有附件、站点配置），附站点与编号映射。PostgreSQL 用 `pg_dump -Fc` 导出所有非模板数据库（包括 Dify 插件库），另存角色定义；库名只接受字母、数字、下划线、连字符。停写后从 API 和插件容器复制 storage 卷为 tar；同时复制 Caddy 的 `/data`（HTTPS 证书，避免恢复后重新申请撞上签发频率限制）为 `caddy.tar`，启用了企业微信入口时复制 dify-on-wechat 的 `/app/data`（会话对应关系）为 `wechat.tar`。`caddy_config` 是 Caddy 自动保存的运行配置，启动时会按 Caddyfile 重新生成，不收集。Qdrant 仅支持当前单节点部署，使用官方 [全存储快照接口](https://api.qdrant.tech/v-1-15-x/api-reference/snapshots/create-full-snapshot)，核对大小及服务端 SHA256（存在时），下载结束或失败后删除本次新快照，不复制在线存储目录。临时读取容器关闭 Docker 日志，退出后删除；原始命令错误输出不进入日志，错误只保留组件和类型。Frappe 明文副本放在站点卷的 `.eb-backup-*` 目录，每次结束都删除全部此类目录（包括以前失败留下的）；备份本身已失败时，即使清理也失败，报出的仍是原来的错误。实际镜像版本与镜像 ID 返回给加密清单入口。

`make -C deploy verify` 已纳入命令协议测试：多站点、多数据库、600 权限、证书与会话数据、各收集阶段失败、清理失败不盖掉原错误、停止/恢复失败、恢复后健康检查及敏感输出隔离。这里使用 Docker 替身，未声称执行整套 Docker 部署；真实 Frappe 恢复证据见 [恢复演练](P3-Frappe恢复演练.md)。真实 PostgreSQL/Qdrant 收集及完整恢复仍待测试环境验证。暂存区包含明文数据，完整入口必须在加密后或任何失败时清理；不可上传到 CI 附件。
