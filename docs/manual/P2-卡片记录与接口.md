# 审批卡片记录与接口底座（P2-G2，尚未启用推送）

`EB Approval Card` 用于后续记录请假单、审批阶段、唯一任务 ID、接收用户、企业微信 userid、发送/完成状态和处理人。仅 System Manager 可读，没有普通用户/HR/集成账号的建改删权限。更新凭证用原生 Password 字段保存到加密凭据存储，不记录卡片正文，也不导出业务记录为 fixtures。

`enterprise_base.wecom.card_api` 仅允许官方 `message/send` 和 `message/update_template_card`；请求不跟随重定向，异常使用固定文案，不返回 URL、密钥或响应正文。缓存 Token 以企业/Secret 摘要隔离，按上游有效期提前过期；只在上游明确返回 Token 失效时刷新一次，不对结果不明的超时自动重发。

服务器 `site_config.json` 的 `eb_wecom_cards` 配置包含 enabled、corpid、agentid（字符串）、app_secret，默认关闭。真实配置只留服务器密钥文件。此部分没有注册调度器、文档事件或公网回调；后续推送/回调需在官方签名、在职身份、当前审批人和幂等保护全部接通后才能启用。

CI 用合成凭证和替代 HTTP 检查原生加密存储、Guest/EB X4 读取拒绝、固定目标、重定向/无效接收人/Token 失效/超时拒绝及异常脱敏。没有发送真实企业微信消息，不能作为卡片收发验收。配置遵守 [回调协议准备 PR #53](https://github.com/qianjie0720-sys/enterprise-base/pull/53)，该手册随前置 PR 单独交付。

发送时间以带时区的 UTC ISO 8601 文本存储；审批完成和企业微信卡片更新使用独立状态，更新失败不能把已经完成的审批改回待审批。
