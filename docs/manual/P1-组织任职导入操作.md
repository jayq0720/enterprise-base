# 组织任职导入操作（P1-G2）

模板和后端主体已随 #37/#38 合入 main；先合并 #35 的 HR 权限补丁，再部署本页面。更新代码后重新构建 enterprise_base 镜像并运行 `make -C deploy up`，迁移会同步原生 Page，无需在线手工建页面或改权限。仅 HR Manager/System Manager 可打开 `/app/eb-org-import`；后台接口仍独立校验权限，隐藏按钮不能代替权限检查。HR Manager 新建岗位还须保留原生 HR User 角色，HR User 单独不能导入。

HR 先在后台建立真实员工档案及工号，再按[模板说明](P1-组织导入模板.md)填写。选择对应公司，点“上传 xlsx”，保持文件私有，然后“预检”。错误列表按工作表、Excel 行号和列定位，修正后重新上传；检查各表数量后点“整批保存”。保存会重新预检，并非复用之前的结果。整批失败时不保留部门、岗位或任职变更。

工号须已有且唯一；姓名仅用于核对，不修改姓名、用户、状态或敏感信息。System Manager 若不兼任 HR Manager，不可借导入改变企业微信身份或知识空间授权；需要这些变更时由 HR Manager 执行。企业微信 userid、入职日期留空保留原值；空的知识空间列会清空该岗位额外空间，空的直属上级列会清空 reports_to，上传前请核对。职责空白拒绝，避免误清空。

在测试环境先用合成数据预检/保存，再重复导入并核对数量不增加；尝试无权限账号、敏感字段新增列及错误引用，应被拒绝且无业务变化。用测试员工通过 X4 查询本人职责，与导入内容比对。只回传去密钥、去个人内容的数量和通过/失败摘要。真实后台浏览器操作、X4 联测及企业微信链路仍待测试服务器，不能用 CI 静态检查替代。
