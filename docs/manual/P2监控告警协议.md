# 监控告警发送协议（开发验收）

任务 P2-G5。使用 Python 标准库，无新增依赖。已接入 make health 总入口；定时安装和真实机器人由 JQ 在服务器上执行。

- 调用方持维护锁；状态以 600 权限原子保存到忽略的 data 目录，不记录 Webhook。
- 首次故障发送一次，此后同一检查项每小时最多尝试一次；恢复时发送“已恢复”。
- HTTP 超时或机器人拒绝后不立即重试，避免不确定结果刷屏；恢复通知失败也按小时重试。
- 地址未配置时只写本机日志。发送失败只输出异常类型，不输出请求、响应或地址。
- 请求仅包含组件检查名、有限数值和 UTC 时间；拒绝非检查键、字符串数值和非有限数值。
- 本机模拟 HTTP 服务验证实际请求、小时边界、恢复、失败重试和脱敏；make verify 执行。
- 本模块测试不代表企业微信群机器人真机联测通过。实际地址只放服务器 secrets/.env。

## 手动检查

在仓库根目录运行 `make -C deploy health`。当前部署配置必须是本人所有的700目录/600文件；在私有secrets/.env填写空白示例中的EB_HEALTH_*，Webhook只接受无用户信息的HTTPS地址。未配置Webhook只写日志，检查失败正常结束；配置、权限或状态文件损坏则非零退出。

首次故障通知一次，持续故障每小时最多提醒一次，不视为重复故障；恢复发一次“已恢复”。HTTP超时也受限频。每项输出只有检查名、通过/失败、数值；退出码0不等于业务全健康。

备份/恢复/发布持维护锁时跳过，不发送误报或恢复消息。只在正式活动环境启用定时器；隔离恢复副本按设计暂停调度，会报scheduler异常。EB_HEALTH_PROFILES按实际启用功能填写，可发现整个可选服务组缺失；未填仍检查已存在的可选服务。

磁盘检查沿用main中Claude的匿名卷修复，只统计本项目命名卷；不把跳过匿名卷当成跳过未知来源卷。内部HTTP与进程健康不替代真实白名单、模型、权限和企业微信验收。完整systemd安装步骤待运维正式手册#105前置齐全后审核，本次不安装。
