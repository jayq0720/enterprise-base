# P2-G2 统一消息和审批回调

企业微信同一自建应用只有一个接收消息 URL。此入口先用官方协议验签、限时解密及校验企业/应用，再把模板卡片事件交给本人权限处理器；其他消息的原始密文和三项查询参数转发到固定内网 `http://wechat:9898/wxcomapp`，保留原 dify-on-wechat 聊天。只返回成功确认或加密回复，不透传重定向、Cookie 或错误正文。带 MsgId 的普通消息用 Redis 原子占位及短期加密回复缓存去重。

前置 PR：[#51 请假流程](https://github.com/qianjie0720-sys/enterprise-base/pull/51)、[#53 协议](https://github.com/qianjie0720-sys/enterprise-base/pull/53)、[#54 记录](https://github.com/qianjie0720-sys/enterprise-base/pull/54)、[#55 发送](https://github.com/qianjie0720-sys/enterprise-base/pull/55)、[#56 动作](https://github.com/qianjie0720-sys/enterprise-base/pull/56)，均已合入 main；从包含这些模块的版本构建。缺协议模块或未启用时返回 503；公网接线和默认 bridge 开关沿用 #58，启用须按部署手册先做测试环境验收。

服务器私有 `site_config.json` 的 `eb_wecom_cards` 增加 token、aes_key，必须与 dify-on-wechat 的接收 Token/EncodingAESKey、corpid、agentid 属于同一应用；原 app_secret、desk_url 保留。真实值只由管理员在服务器配置。不要关闭站点 CSRF；此接口仅接受无 Cookie、无 Authorization 的企业微信请求，动作身份来自已验签的 userid。

公开目标方法为 `/api/method/enterprise_base.wecom.callback.receive`。入口无条件校验地址；before_request Hook 同时拦截 v1/v2、末尾斜杠及 cmd 兼容入口，再限定 GET/POST、唯一且完整的参数（GET 加 echostr）、XML 和 64 KiB 上限，拒绝 cmd 等额外参数，防止 Frappe 兼容路由绕过目标方法。部署时不要开启 enable_frappe_logger、monitor 或原始请求追踪；#58 启用脚本负责关闭前两项；应用不记录回调正文、密文、签名和异常。

HTTP 测试同时保留替代对象分流检查及真实 crypto 加解密请求；真实签名用例无跳过，缺依赖即失败，并在成功后输出固定测试名 test_real_signature_http。覆盖签名 GET/POST、CDATA HTML、伪签名、过期有效签名和错误 CorpID。网络依赖 #58 的专用内部桥接网络，须一起部署；加解密独立向量见 #53。尚未完成真实企业微信收卡→回调→审批→卡片更新、普通消息并行回归，不应据此启用生产。
