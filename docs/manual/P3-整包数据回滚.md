# 整包数据回滚执行段

`rollback_data.py` 供发布回滚总入口调用，不提供独立覆盖CLI。主机先持维护锁，使用离线私钥解密、核对发布记录的项目与提交、校验全部SHA256和负载，并确认原精确镜像仍在；停写前完成这些检查。数据覆盖要求交互终端，两次分别输入目标项目和固定确认语句，管道或自动yes不能代替确认。将丢失发布后产生的数据。

覆盖前确认全部应用和Qdrant已停，按原项目及原镜像建立停止的容器，保留目标数据库账号、口令和卷归属验证。全部卷和归档先预检，再恢复PostgreSQL；文件、插件、Caddy证书和企业微信会话清空后解包，Qdrant使用原生全快照恢复。原数据库/文件只在已明确覆盖的路径修改，普通make restore仍只允许新项目。

恢复后清空旧任务队列和缓存，避免执行指向备份之后记录的过期任务。Frappe configurator与原backend一致，已有站点恢复保留目标数据库身份，只复制解密密钥；主机入口最后启动旧版服务并自检。任何失败继续保持应用停止，由入口写rollback-failed。解密暂存区结束清除，私钥不复制进服务器配置。恢复前后必须复核离职停用、权限、接口凭据和企业微信；外部发送结果无法随数据库倒退，应按运维手册重新核对。

测试使用真实age、归档与私有暂存目录，验证来源/提交匹配、终端二次确认、在线写入拒绝、全部卷预检早于数据库写入及已有站点传输参数；Docker写入用协议替身。原生Frappe和PostgreSQL各自另有CI演练，整套生产回滚仍须Claude云端联测，不据此勾选全栈验收。无新增依赖，不改上游或.github/。

PostgreSQL覆盖中途失败时可能留下空库，调用方须保持应用停止、保留发布前加密包；修复原因后可用同一包重新执行完整回滚，每次都重新预检并二次确认，不自动重试或接回流量。协议测试覆盖先失败、用同一解密输入重试成功。
